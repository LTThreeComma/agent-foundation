# Validation: challenge protocols before expanding features

This document defines acceptance for the new Service; it does not certify an implementation. The central trade is explicit: run-owned input assignments; immutable run objects made reachable only by a fenced pointer commit that also confirms consumption; a durable display committed with each checkpoint and a provisional per-thread stream in between; and durable operation identity where external effects cannot share a transaction. Measure those costs instead of relying on fewer tables or a smaller number of status names.

## New tests and live journeys

Only tests of the new system establish rewrite acceptance. Write `packages/a13n-service/tests/` against the current design and new implementation. Legacy tests need not be maintained, ported, collected or made to pass; their old assertions are not compatibility requirements. Shared Harness/library suites retain their own checks. [11](11-transition.md#package-placement-and-build-boundary) owns package identity and legacy isolation.

Replace the old Service journeys in `dev/live_tests` with new-system journeys, including their fixtures, configuration, process launchers, clients, CI selections, support tests and README commands. They must start the new Service, apply its migrations to isolated stores and use the new public contracts. Remove obsolete Service cases and stale case-count/skip expectations instead of retaining a second legacy live suite or compatibility router. Generic infrastructure helpers may be reused after verifying that they contain no old Service imports or behavior assumptions. Bot/platform integrations and WebSocket envd are outside the suite; HTTP envd remains in scope.

| Test surface         | Evidence it provides                                                                                                                                                                                           |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| New package tests    | Focused business-rule checks and integrations through production functions; real storage and concurrent transactions for database, lease, pointer and stream guarantees                                        |
| New `dev/live_tests` | Public API and supported Console journeys through real Control/Worker processes, Harness execution, persistent stores and environment operations; process/dependency faults exercised at observable boundaries |
| Design probes        | Isolated models and counterexamples used to understand protocols; never a substitute for either implementation suite                                                                                           |

A deterministic model or controlled remote endpoint is appropriate for reproducible inputs and injected failures. It must not replace the Harness or the coordination/storage mechanism whose guarantee is being tested. Verify PostgreSQL/Redis behavior on real instances and object create/read/list/delete on the advertised local/S3 backends; use real HTTP envd for its integration gate. External-provider credentials or unavailable dependencies leave the corresponding qualification unverified, not passed. Small mocked tests do not establish remote idempotence or unknown-outcome recovery.

CI and local commands must select the new tests explicitly, rebuild stale test-impact mappings, and report the actual collected/executed/skipped cases. A command that selects no tests or skips a required gate is not successful acceptance. Test counts, coverage percentages and file counts alone are not completion criteria.

## Decision method

For each path, write the normal sequence and move a crash, timeout, concurrent request or revocation between every pair of externally visible actions. Ask what evidence survives, which actor owns recovery, and whether replay is safe. Compare models before adding exceptions. A recovery rule must be executable from stored facts, not from an operator's guess about which line a worker reached.

| Model choice                                                | Counterexample to the rejected alternative                                                                                                           | Why this model                                                                                                                   |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Run assignment distinct from consumption                    | Offer succeeds, incorporation has not happened; marking consumed loses input                                                                         | Assignment gives editing exclusion and recovery ownership; the checkpoint commit establishes consumption                         |
| No durable offered state                                    | Handoff leaves offered inputs that only crash recovery resets                                                                                        | Attempt-local offer state disappears on replacement; run assignment is unchanged                                                 |
| Immutable run objects behind a fenced pointer               | A fixed key overwritten by a stale or unconfirmed write leaves bytes ahead of the database, forcing receipt repair and object-versus-seal race rules | Only the fenced commit makes bytes reachable, and consumption commits with the pointer; late bytes are garbage the owner deletes |
| Display committed with the checkpoint                       | Display flushed ahead of the checkpoint shows output the restored run never produced, requiring attempt segments and two-object ordering             | The durable view always equals the restored history; only provisional output after the last checkpoint can disappear on a crash  |
| Owner-driven run object cleanup; no other reclamation in v1 | A collector observes an unused upload just before a publisher commits its reference                                                                  | Keep unused payloads; only a run's own attempts and sealers delete its unreferenced state/display objects                        |
| Resume binds an idle waiting head                           | Two answers validate against the same old head while its successor runs                                                                              | The exact target check under the thread lock prevents stale approval                                                             |
| Waiting eligibility examines every pending item             | A normal message arrives while a question and an approval are both pending                                                                           | Only question-only waits accept ordinary messages; mixed waits preserve the approval                                             |
| Resume identifies the waiting run and tool call             | The same call suspends again for another approval source; an old UI submits a fresh request key                                                      | The old waiting run is no longer the head, so the request conflicts even when the call ID matches                                |
| Resume outside the inbox                                    | Queued messages fill the inbox while a run waits for approval                                                                                        | Answers never occupy inbox capacity; the inbox holds only queued input                                                           |
| Sealing separate from successor/parent work                 | Parent lock contention or admission rejection holds up terminal commit                                                                               | Durable sweep/outbox evidence closes the post-commit crash window                                                                |
| No workspace-ordered lifecycle feed                         | A gap-free workspace cursor serializes every lifecycle commit of a workspace behind one counter row, for a feed no v1 client reads                   | Webhook rows commit with the transition; clients re-read current state                                                           |
| Thread-level caller headers                                 | Per-message headers force steer matching to compare projected maps and leave Console messages without conversation context                           | The thread owns its conversation context; runs freeze it; steering ignores it                                                    |
| Live templates without revisions                            | A template revision the agent does not pin gives neither reproducibility nor prompt safety updates                                                   | Operations read the current template; properties built into an instance stay with it                                             |
| One provisional stream per thread                           | Per-run streams leave clients blind to successor runs and inbox changes; a session stream makes a thread view filter unrelated output                | The gateway derives `changed`/`reset`/`gap` from database reads; Redis carries only output                                       |
| Accepted mount snapshot                                     | Removing a desired mount hides an active run from idle cleanup                                                                                       | Immutable run references provide active-use evidence across recovery                                                             |
| One external operation at a time                            | Timeout followed by resume; the old stop completes later                                                                                             | Reconcile the same operation; unknown is a real outcome, not permission to retry                                                 |
| OAuth claim before network                                  | Two CAS contenders both rotate the same token before either writes back                                                                              | Single dispatch owner plus generation prevents both duplicate use and stale publication                                          |

## Evidence required from implementation

Historical models and protocol experiments are not included in this handoff and establish no pass for the new Service. Every applicable gate below requires evidence from the new implementation. Record real commands, dependencies and results; absence of evidence remains unverified.

## Execution spine gates

| Path / injected schedule                                                                                                                      | Required result                                                                                                                                                                                                               |
| --------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Two new-thread submissions with one key, response lost                                                                                        | One thread/session/entry/run; losing transaction leaves no rows; differing digest conflicts                                                                                                                                   |
| Pending entry edited or withdrawn while a worker binds it                                                                                     | One lock winner; assigned input is immutable; tombstone retains replay identity                                                                                                                                               |
| Inbox at capacity; assignment, concurrent submission, unincorporated return, recovery and repeated commits                                    | Pending plus assigned entries remain bounded in count/bytes; assignment/return/recovery preserve occupancy; consumption or terminal disposition releases once; a full inbox leaves valid child delivery retryable             |
| Crash before offer, after incorporation, after object write, or after the checkpoint commit while the run remains recoverable                 | Recovery uses only the committed pointers; entries consumed in that commit are never reoffered; still-assigned entries are reoffered once; unreferenced objects are deleted before execution; terminal disposition still wins |
| Unsafe tool completes but no result checkpoint commits                                                                                        | Pending-call checkpoint or durable operation receipt preserves its identity; declared recovery never assumes non-execution                                                                                                    |
| Compaction before checkpoint; delayed observer event                                                                                          | Awaited incorporation evidence survives outside history; no reliance on observer timing                                                                                                                                       |
| Two workers claim; heartbeat while provider is slow                                                                                           | One current attempt, bounded local slots, independent renewal; late writer rejected                                                                                                                                           |
| Concurrent `wake()` producers; idle and full workers in the claim loop                                                                        | The list holds at most one marker; a full worker never takes it; the database claim arbitrates ownership                                                                                                                      |
| Acceptance commits but its after-commit wake is lost; Redis unavailable; backoff becomes due; startup, slot release or shutdown during a wait | The periodic scan (`BLPOP` timeout or error sleep) finds eligible runs within one interval; slot release and startup scan immediately; one loop per worker; no tight failure loop; waits are cancellable                      |
| Lease expires while a transaction waits for locks                                                                                             | Fresh-time predicate rejects; heartbeat cannot revive the expired attempt                                                                                                                                                     |
| Object write response lost; checkpoint commit acknowledgement lost                                                                            | Readback compares exact bytes before reuse; rereading the pointer decides whether the commit happened; nothing is blindly retried                                                                                             |
| Stale attempt writes state/display objects after takeover or seal                                                                             | The bytes are never referenced and cannot change lifecycle, pointers or inbox disposition; takeover or seal cleanup deletes them; writes never start within one write timeout of the lease deadline                           |
| Crash between a checkpoint commit and deletion of superseded objects; crash of a sealer before its cleanup                                    | Takeover cleanup removes the first; the second leaves bounded, measured leftovers only after a double fault                                                                                                                   |
| Worker seal races expiry, interrupt, or another checkpoint commit                                                                             | Exactly one terminal outcome; pointers and consumption coherent; late usage still retained                                                                                                                                    |
| Failed/cancelled seal wins over a pending checkpoint commit                                                                                   | Still-assigned entries fail and stay failed; the losing commit's objects stay unreferenced; consumed entries stay consumed; capacity is released once                                                                         |
| Final checkpoint commits, the seal is lost; later takeover                                                                                    | Restore from the pointer, find the completed/waiting outcome and seal without repeating model/tool work; an intervening terminal seal wins                                                                                    |
| Handoff with an offered but unincorporated entry                                                                                              | Replacement sees the assignment and reoffers it once, without stranding or double-source input                                                                                                                                |
| Steer arrives at final boundary                                                                                                               | If unincorporated at completed/waiting seal, it returns pending; failed/cancelled never automatically rerun assigned work                                                                                                     |
| Question-only wait; earlier child result and then an ordinary reply                                                                           | Skip the child result as a source, complete unanswered question calls with no-response results and incorporate the message once; normal message revision/options/identity rules apply                                         |
| Approval, client-tool or mixed wait with queued ordinary messages                                                                             | Messages and child results stay pending in place; only resume starts a successor                                                                                                                                              |
| Resume starts a successor while earlier messages are queued; they become compatible steers                                                    | The resume answers apply first, then eligible steers in FIFO order                                                                                                                                                            |
| Resume with partial or empty answers                                                                                                          | Normalize the exact pending set once: omitted approvals denied, client results and mixed user questions unanswered; create one successor without partial-approval state                                                       |
| Resume naming unknown/duplicate calls or using a wrong answer action; oversized request or one carrying message payload/options               | Reject the request by resume's own bounds and typed fields; nothing is stored                                                                                                                                                 |
| Same tool call asks for a second approval; old card submitted again, with both reused and new request keys                                    | A reused key returns the original successor; a fresh key for the old waiting run conflicts and cannot approve the new suspension                                                                                              |
| Full inbox; concurrent resumes, lost acknowledgement and attempt recovery                                                                     | Resume ignores inbox occupancy; one successor, the other request conflicts; replay returns the original successor; recovery does not reapply answers already in a checkpoint                                                  |
| Resume of a run that is no longer the idle waiting head                                                                                       | Conflict; answers never approve another wait or become model text                                                                                                                                                             |
| Successor of a resumed wait fails/cancels; user submits an ordinary message and then resumes                                                  | Failure still pauses automatic advancement; the message remains pending while the head requires answers; an explicit resume restarts from that unchanged head                                                                 |
| Explicit fork of an approval wait                                                                                                             | New branch receives denied/no-response inherited results, never approval; original thread remains waiting                                                                                                                     |
| Cancel poem, then submit hello                                                                                                                | Hello starts from the last good head; poem inputs are not silently replayed                                                                                                                                                   |
| Fork's first run and further resubmissions fail/cancel before any local head exists                                                           | Each explicit submission retains the original fork baseline; after completed/waiting creates a local head, subsequent runs use that head                                                                                      |
| Thread headers edited while a run is active; child spawned; fork created; message submitted from the Console                                  | The active run keeps its frozen map; the next run uses the edited map; the child copies the parent run's map and the fork the thread's map; messages steer regardless of headers; headers never grant tool access             |
| Spawn commit succeeds but parent checkpoint loses the result                                                                                  | Stable tool-call key returns the existing child; stale parent attempt cannot spawn                                                                                                                                            |
| Child waits then completes; delivery retries; parent fails/archives concurrently                                                              | One result per terminal child run; correct origin eligibility or explicit ignored disposition                                                                                                                                 |
| Seal commits, process dies before advancing thread                                                                                            | Advancement sweep finds durable work; no stuck queue or rollback of the seal                                                                                                                                                  |

## Storage, streaming and external-operation gates

| Path / injected schedule                                                                                                                | Required result                                                                                                                                                                                                                                                   |
| --------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stale attempt appends deltas to the thread stream after takeover                                                                        | The gateway drops deltas of attempts older than the current one; `reset` corrects anything already shown; the gateway reflects PostgreSQL                                                                                                                         |
| Redis flushed or unavailable, or the stream trimmed by `MAXLEN` during a long boundary                                                  | Execution is unaffected; affected clients get `gap` and the durable view catches up at the next boundary marker; no reset loop                                                                                                                                    |
| Inbox edit, thread `PATCH` or sweep seal by another caller while a client watches                                                       | `changed` arrives within one authority interval; the client's re-read shows the new version                                                                                                                                                                       |
| Long tool stream exceeds item/count/byte limits                                                                                         | No loss of accepted input and no unbounded memory; output externalization or explicit failure                                                                                                                                                                     |
| Worker crash after streaming output past the last checkpoint                                                                            | The durable view equals the restored history; the provisional tail disappears and is regenerated; an unsafe tool call committed before dispatch stays visible                                                                                                     |
| Worker seals failed/cancelled with an in-memory tail; sweep seals after worker loss                                                     | The worker tail is committed as an interrupted display object; the sweep writes nothing and readers render `in_progress` items as interrupted                                                                                                                     |
| Fork/continue reads a completed/waiting run while its successor commits                                                                 | Frozen pointers validate; the successor writes under its own prefix and cannot replace its parent's objects                                                                                                                                                       |
| Repeated checkpoints; rolled-back payload reference; old unused upload                                                                  | One referenced state/display pair per run after cleanup; unused payloads retained, no age-based deletion                                                                                                                                                          |
| Asset retired while input/output still refers to it                                                                                     | Existing authorized history retains content; new selection refuses retired asset                                                                                                                                                                                  |
| Shared sandbox active through another thread, handoff or mount removal                                                                  | No idle stop/destroy while accepted active-use evidence exists                                                                                                                                                                                                    |
| Process dies before/after create, stop, start, destroy dispatch or result commit                                                        | Reconcile the same operation; never issue conflicting work on timeout alone                                                                                                                                                                                       |
| Provider returns multiple instances for one label or cannot establish outcome                                                           | No arbitrary adoption or conflicting operation; original lifecycle phase, operation identity and actionable failure remain visible                                                                                                                                |
| Environment stop repeatedly times out, then completes; delayed duplicate arrives after a later start                                    | Fixed-interval maintenance revisits stopping with the same operation ID, records errors and confirms completion safely; no per-environment retry schedule or delayed duplicate stopping the restarted instance                                                    |
| Registered HTTP envd is used, becomes idle, loses HTTP connectivity or closes its Session                                               | Direct HTTP use of the authorized frozen mount; no relay or presence dependency; no automatic daemon create/start/stop/destroy or silent replacement; unreachable preparation reports environment_unavailable                                                     |
| HTTP envd endpoint/native identity changes, credentials rotate, or a mutation response is lost                                          | Identity mismatch refuses use; fresh credentials reach the adapter; unknown effects are not blindly replayed; old Session/operation handles cannot cross device generations                                                                                       |
| Two OAuth callers, revoke/reauthorize during refresh, lost rotating-token response; connector account setup or completion response lost | One external dispatch per operation; no stale credential revival; unknown requires safe recovery or reauthorization                                                                                                                                               |
| Template network policy or limits edited; image or storage mode edited                                                                  | Existing environments apply the current runtime settings at their next start/open where the adapter supports it; built-in properties change only for environments created afterwards; a disabled template refuses new environments without breaking existing ones |
| Lifecycle transition commits or rolls back with matching subscriptions                                                                  | Webhook outbox rows exist exactly when the transition committed, one per matching subscription                                                                                                                                                                    |
| Delivery acknowledgement lost; subscription edited/deleted/key rotated                                                                  | Stable duplicate delivery identity; frozen URL/key decryptable with destination AAD; stale claimant cannot settle                                                                                                                                                 |

## Distribution, security and operational gates

A tiny distribution adds a role, source of grants, resource/table/migration, provider, settings and extra admission policy. Exercise all creation paths without modifying the core or bypassing its authorization. A fake budget refuses at `accept` and at `proceed` for parent, child and inline calls, and is checked against late usage records by `call_id`. This is the #410 seam test, not a billing implementation.

Exercise paid tools and auxiliary model calls through the real Harness, including enabled compaction, media-understanding and tool-review paths. Verify that cancellation, lost authority or a limit/policy rejection prevents the affected provider dispatch, rather than merely recording a rejection afterward. For admitted concurrent calls, return usage out of order and after seal; each report must retain the `call_id` observed before its dispatch, while duplicate reports remain idempotent under the usage-record rules. Usage totals or a passing main-agent case alone do not prove this coverage.

Exercise several concurrent calls that all pass `proceed` before their usage arrives. They may collectively exceed the soft budget; after recorded usage reaches the limit, further dispatch must be refused. The fixture must not assert a one-call overshoot bound or introduce a hidden reservation ledger to make that assertion pass.

Negative tenant tests cover foreign keys, shared providers, connection credentials, private secrets/devices, asset content, traces, thread streams, replay lookup and background tasks. Unknown roles deny access. Key confinement persists in accepted authority. Authenticator replacement preserves management behavior. Application DB roles cannot bypass immutability through a writable session setting.

Key-issuance tests use a principal with grants in workspaces A and B in one organization and C in another. An A key can issue only another A key under ordinary issuance authority; B/C requests are forbidden, and omitted/null workspace on user-key creation is invalid. Service-account keys must match the route and account's home workspace. The schema rejects keys without a workspace or with a mismatched organization. A login session may issue separate keys for authorized workspaces; no flow or Console control offers organization/global keys. Exercise user, service-account and service-tool issuance paths.

Using an A key, verify that requests, replay lookup, streams and key list/read/revoke cannot access B/C, even when the principal has grants there. Reading/using A's organization-shared providers remains allowed by current grants; modifying shared resources and organization administration are denied. Verify organization management through an authorized login session and that accepted runs, children and service tools retain A confinement. Revoking grants or disabling the principal reduces effective authority under the existing refresh rules; issuing a key never grants additional verbs.

Before broad rollout, define representative concurrency and latency targets for expected workspace sizes. Measure claim fairness and wake latency, checkpoint commit cost and object sizes, leftover run objects, gateway authority-read load, outbox drain, environment reconciliation and queue backlogs at and beyond those targets. The design intentionally does not invent a product QPS requirement. Provider qualification includes real timeout/duplicate-request behavior, not only mocked success paths.

## Implementation acceptance record

Maintain one acceptance record linking each in-scope design requirement to its implementation, tests and evidence. For each gate record design/implementation revisions, test location, command/scenario, dependencies, observed result and remaining limitation. Distinguish passed, failed and not run; a skipped check or unavailable dependency remains unverified. Only an explicit scope change can remove an applicable gate.

The fault schedules in this chapter supplement normal feature coverage; they are not the entire product test plan. Acceptance also covers the following delivery paths:

A first execution slice, a minimal Console or passing model probes is a milestone, not completion. The rewrite is complete only when its in-scope capabilities are implemented and all applicable new-test gates have passing evidence; outstanding externally owned consumer changes must be identified, not claimed complete by a local export. Implementation completion does not authorize a production switch, which follows [11](11-transition.md#sequence-and-switch-gates).

Fix ordinary implementation defects against the current contract. When a failure exposes a missing owner or contradictory protocol, resolve it in the owning design section before proceeding with that behavior; do not weaken the assertion merely to obtain a pass. Do not mark a review point resolved just because prose or a matching test was added.

## Package and provider boundaries

Check object-ID allocation against [layout](02-layout.md#id-prefixes) and the platform data conventions: retained kind prefixes, cryptographic lowercase-hex suffixes at the assigned lengths, 32-character defaults for new kinds, and no per-caller length overrides. Verify acceptance separately, including existing alphanumeric IDs and legacy Thread forms at supported boundaries. Inject a duplicate allocation and verify that it cannot overwrite an object. Externally owned IDs and secret material keep their own formats; consumers cannot derive authority or event ordering from an object ID.

Import checks cover `infra` as the shared lower layer and reject business or startup imports from it. Moving a large module into a package must preserve its public interface and import direction; consumers must not reach into its split internals. Generic outbox persistence and sweep scheduling remain separate from registered business handlers.

Exercise two configured Web accounts of one provider type and verify the selected account's configuration and credential reach the shared Harness implementation. Fetch/download must work without a Web-provider record while retaining tool enablement, URL policy, response bounds and authorization checks. Search/scrape still validate the selected provider resource. These are implementation gates; terminology and package-tree edits are not runtime evidence.
